# luzid.co — accessibility

The page is one link: the name `Tomasz Cudziło`, as large as the screen allows, pointing at
github.com/tomasz. This file records the accessibility policy that `contracts.md` §5.1 and
§5.8 implement, the one accepted deviation, and the checks that no automated test covers.
`contracts.md` wins where the two disagree; changing the policy here is a `contract` PR.

## What is always true

- **Real text.** The link's accessible name is the text itself, `Tomasz Cudziło`, with
  `lang="pl"` on the document. No `aria-label`, no per-letter spans. Decorative copies are
  generated content with empty alternative text (`content:attr(data-t) / ""`), wrapped in
  `@supports` so an engine without that syntax shows plain text instead of a doubled name.
- **Effects are gated, not reset** (§5.8). Every effect rule sits inside
  `@media screen and (forced-colors:none) and (prefers-contrast:no-preference)`. Forced
  colours get the user agent's own colours, `prefers-contrast:more` gets near-black on white
  (or the reverse on dark role sets), print gets black on no background. A unit test fails if
  an effect selector appears outside the gate.
- **Contrast.** Every role set's `--fg` on `--bg` is at least 3:1 (§5.4), the WCAG 1.4.3
  threshold for large text; the name is always large text.
- **Focus.** `a.n:focus-visible` draws a solid outline in `--fg`, at least 3 px wide and 4 px
  outside the name's box. It fits inside the page margin (`--m`, at least 12 px), so
  `overflow:clip` never cuts it.
- **Zoom is never blocked.** The viewport meta sets no `maximum-scale` and no
  `user-scalable`.

## Reduced motion (D6)

Under `prefers-reduced-motion:reduce` the page keeps its hover and active **states** and
drops their **animation**:

- Gated: the renderer's `transition` list (`.18s` on `scale`, `translate`, `filter`,
  `opacity`, `text-shadow`) and any `motion` CSS. They are emitted only inside
  `@media (prefers-reduced-motion:no-preference)`.
- Not gated: the hover and active declarations themselves, including geometry. The shared
  default `a.n:active{scale:.985}` and any `translate` or `scale` an effect declares in
  `hover` still apply, instantly.

The reasoning: the motion WCAG 2.3.3 is concerned with is animation, and with transitions
gone a state change is a jump between two still frames, not movement. The press feedback a
1.5% scale gives is the only sign the link responded, and it is worth keeping for everyone.
The audit that raised this called it a policy inconsistency rather than a WCAG failure, and
the owner chose to keep the behaviour and record it here. If it ever changes, the hover
declarations move inside the reduced-motion block in `src/render.js` and §5.6 and §5.8 of
`contracts.md` change with them.

## Accepted deviation: WCAG 1.4.4 Resize Text

The name is sized from the viewport (`--bw` is computed from `100vw` and `100svh`), not from
the user's font size, and `text-size-adjust:100%` stops mobile browsers inflating it.
Consequences:

- **Text-only zoom does nothing** (Firefox "Zoom Text Only", Safari's text-size setting).
- **Browser page zoom does not make it bigger.** Desktop zoom shrinks the viewport in CSS
  pixels, and the name refits to the same on-screen size.
- **Pinch zoom works** on touch devices and magnifies it like any other page.

This is accepted because the text already fills the screen: there is no larger size it could
be resized to without clipping, and the real text is always there for assistive technology
and for the user agent's own magnifier.

## Manual checks

Run these after any change to `src/render.js`, the fit, the font pipeline or a new font, on
a real device where the step says so. Record the result in the PR body.

1. **Page zoom.** In Chrome, Firefox and Safari on a desktop, zoom to 200% and to 400%. The
   name stays whole and centred, nothing is clipped, no scrollbar appears.
2. **Text-only zoom.** Firefox, View → Zoom → Zoom Text Only, at 200%. The page must not
   break; the name keeps its size (the deviation above).
3. **Pinch zoom.** iOS Safari and Android Chrome: pinch-zoom magnifies the name and pans
   normally. Rotate the device once: the layout refits.
4. **Keyboard.** Tab once: the focus outline is visible on every side, including on a
   `side` (rotated) look. Enter follows the link.
5. **Preferences.** In the browser's dev tools, emulate `prefers-contrast: more`,
   `forced-colors: active` and `prefers-reduced-motion: reduce` in turn. The first two show
   the plain name with no effect; the third keeps the effect and the hover state but nothing
   animates.

## WebKit in CI is not Safari

Playwright's WebKit on Linux (which CI runs) is WPE, shaping text with HarfBuzz and FreeType.
Safari on macOS and iOS shapes with CoreText. The build measures ink with HarfBuzz, so Linux
WebKit agrees with the build by construction, and a green WebKit run in CI says nothing about
what CoreText does. The two divergences found so far are measured in [`fit.md`](fit.md),
and the font pipeline now prevents both: CoreText ignores `fina` on Latin (the former
`pacifico.n-fina-static` painted 1.97% wider than measured on line 1, more than the 1.5% the
fit's `SAFETY` factor leaves), which is why the pipeline denies `fina init medi isol`; and
Linux WebKit applies Bungee's `ss12` placement with the opposite sign, which is why it
rejects placement-only features. A name wider than measured is clipped by `overflow:clip`, which is lost content,
so check 1 above is done in real Safari, not in CI's WebKit.
